# Макеты интерфейса Frontol в пакете настроек

Контракт для `fc`. Новых hub-методов нет: секция едет внутри уже существующего `FrontolSettings`. Транспорт тот же, что у настроек документов: `Docs/frontol-document-settings.md`.

Агент читает и пишет таблицу `TOUCHLAYT`. В пакете нет `id` базы и нет полей внутренней синхронизации Frontol (`bdoCode`, `chng`, `ownerBdo`). Ключ строки — `code`.

| Что | Где |
| --- | --- |
| Секция | `FrontolSettings.UserInterface` — `src/core/Domain/Frontol/Models/Settings/` |
| Чтение и запись | `TouchLayoutRepository` |
| Вложение в пакет | `FrontolSettingsService.ReadFrontolSettings` / `ApplySettings` |

`FrontolSettingsApplying` агент шлёт после попытки записи всего пакета, включая макеты. Успех — `success: true`. Ошибка записи — `success: false` и `message` с текстом. Во время сервисного обслуживания ответ не шлётся.

Если касса не смогла прочитать настройки, ответа `FrontolSettings` тоже нет.

## Секция

Свойство объекта `settings`:

| Свойство | Таблица | Ключ строки |
| --- | --- | --- |
| `userInterface.layout` | `TOUCHLAYT` | `code` |

Повтор кода в одном списке: агент берёт последний элемент.

`data` — строка Base64, как `fastReport` у шаблонов документов. Пустой макет — `""`.

### `null` и пустой массив

| Значение | Что делает агент |
| --- | --- |
| `userInterface` нет, `userInterface: null` или `layout` нет / `null` | таблицу не читает на запись и не удаляет из неё строки |
| `layout: []` | ничего не удаляет и не пишет |
| массив с элементами | нет строки с таким `code` — вставка, есть — обновление `name` и `data`. Остальные строки остаются |

Пустой массив макеты не очищает. Удалить строку `TOUCHLAYT` этим пакетом нельзя.

При выгрузке с кассы `layout` есть всегда, если таблица в базе Frontol есть (в том числе `[]`, если строк нет). `null` с кассы значит: таблицы в этой базе нет. Такой `null` обратно на кассу слать как `null`, не подменять на `[]`.

Новая строка получает локальный `id` из генератора кассы. У существующей `id` не меняется. В пакете `id` нет: на другой кассе он другой.

Настройки `TouchScreen*` в `RMInterfaceSetting` хранят `id` строки `TOUCHLAYT`, не `code`. Этот пакет их не передаёт. Стыковать значение `TouchScreen*` с `layout[].code` нельзя.

`name` длиннее 100 символов не записывается: `Apply` возвращает ошибку, макеты и остальные настройки пакета не меняются.

## Пример

```json
{
  "agentToken": "token-agent",
  "messageType": 3,
  "editId": "edit-1",
  "settings": {
    "userInterface": {
      "layout": [
        {
          "code": 1,
          "name": "Основной",
          "data": "AQID"
        }
      ]
    }
  }
}
```

`data: "AQID"` — Base64 байтов `01 02 03`.

## Строка макета, `layout`

| Свойство | Тип | Колонка | Ограничение |
| --- | --- | --- | --- |
| `code` | int | `CODE` | ключ |
| `name` | string | `NAME` | до 100 символов |
| `data` | byte[] | `DATA` | двоичный BLOB, в JSON — Base64 |

## Что сделать в `fc`

Свойство `userInterface` добавить в тот DTO `FrontolSettings`, который уже ходит в `FrontolSettings` / `FrontolSettingsRequest`. Отдельный `MessageType` и метод хаба не заводить.

При сохранении снимка с кассы не заменять отсутствующий `layout` пустым массивом. На кассу отправлять `null`, если макеты менять не нужно. Пустой массив кассу не очистит и ничего в неё не запишет.
